# Markdown 방언 명세 (0.2, 초안)

`@gogum4/editor-markdown`이 쓰고 읽는 Markdown의 규칙이다. 에디터 패키지 설계는 [EDITOR-PACKAGE.md](EDITOR-PACKAGE.md) §6과 P3.
**이 문서의 모든 규칙은 `packages/editor-markdown/fixtures/`의 골든으로 고정돼 있다**(문서 → Markdown, Markdown → 문서, 왕복). 규칙을 바꾸면 골든을 갱신하고 이 문서도 고친다.

## 원칙

1. **Obsidian 호환 Markdown의 상위 집합**이다. 기반은 CommonMark + GFM(표, 취소선, 할 일).
2. **쓰기는 보수적, 읽기는 관대하게.** 우리가 쓰는 문법은 아래 표의 것뿐이고, 읽을 때는 Obsidian 별칭·HTML 일부까지 받는다.
3. **내용을 버리지 않는다.** 읽지 못하는 것은 글자로 남기고 `notices`(안내 문구)로 알린다.
4. 원본은 Yjs/JSON이다. Markdown은 파생물이라 **잃는 것이 있다** — 아래 "알려진 손실" 목록이 전부다.
5. Notion은 **가져오기만** 한다(미검증 — 아래 "검증 상태").

## 인라인

| 마크 | 쓰기 | 비고 |
|---|---|---|
| 굵게 / 기울임 / 취소선 | `**` / `*` / `~~` | |
| 인라인 코드 | `` ` `` (안에 백틱이 있으면 더 긴 표시) | |
| 링크 | `[글](주소)` | `http` `https` `mailto`만 열 수 있는 링크로 읽는다 |
| 밑줄 | `<u>…</u>` | Markdown에 없어서 HTML로 쓰고 안내한다 |
| 페이지 링크 | `[[제목]]` | 제목이 같은 페이지가 여럿이면 모호함(내보내기 계획이 파일 이름을 구분) |
| 인라인 수식 | `$…$` | 줄바꿈은 공백으로. 숫자만 든 `$5$`는 수식이 아니다 |
| 각주 | `[^1]` + 문서 끝 `[^1]: 내용` | 번호는 문서 순서 |

글자 속의 `\ ` `` ` `` `*` `_` `[` `]` `<` `~`는 `\`로 이스케이프하고, 줄 맨 앞의 `#` `-` `+` `>` 와 `1.` 도 이스케이프한다.

## 목록 경계

같은 계열의 목록이 바로 이어지면(글머리·할 일, 또는 번호) Markdown은 한 목록으로 합친다. 그래서 **둘째부터는 기호를 바꿔 쓴다**: 글머리·할 일은 `-` ↔ `*`, 번호는 `.` ↔ `)`.

## 블록 id (`^id`)

내보내기 옵션 `blockIds`가 켜지면(전체 내보내기는 켠다, 한 페이지 복사·내보내기는 끈다) Obsidian의 블록 id를 쓴다.

| 블록 | 쓰기 |
|---|---|
| 문단·제목 | 마지막 줄 끝에 ` ^id` (목록 항목·인용·콜아웃 안의 문단도 같다) |
| 코드·수식·표·이미지 | 블록 아래 **빈 줄 뒤 한 줄**에 `^id` |
| 목록·인용·콜아웃·토글·구분선·페이지 블록 | 쓰지 않는다 — 블록 링크는 글이 있는 블록(위 두 줄)만 가리킬 수 있고, 안의 문단이 자기 id를 가진다. 가져오면 새 id가 생긴다 |
| 블록 링크 | `[[이름#^id]]` (`blockIds`가 꺼지면 페이지 링크 `[[이름]]`로 바뀐다) |

읽기: 줄 끝의 ` ^id`(3글자 이상, 글자 포함 — `x ^2` 같은 지수 표기는 id가 아니다)와 홀로 있는 `^id` 줄(바로 앞 블록의 id)을 읽는다. `[[이름#^id]]`는 블록 링크로 읽고 `[[이름#제목]]`은 위치를 버리고 안내한다. 코드 안의 `^id`는 그대로 둔다.

**id 모양**: 이 앱의 id(소문자·숫자 10글자)는 그대로 쓴다. 다른 모양(Obsidian 사용자가 만든 `^my-quote`)은 글자에서 **정해지는** id로 바꾼다(`blockIdFromForeign`: FNV-1a 64비트 → 36진수 10글자). 블록과 링크를 따로 가져와도 같은 id가 되어 이어진다. 이 값은 고정이다 — 바뀌면 이미 가져온 노트의 블록 링크가 끊어진다.

## 표

GFM 표는 병합 셀, 머리글 없는 표, 셀 안의 여러 블록을 표현하지 못한다.

- 병합 셀은 풀어서 쓴다(남는 칸은 빈 칸). 안내한다.
- 첫 줄을 항상 머리글로 쓴다. 머리글 행이 없던 표는 안내한다.
- 셀 안 문단 여럿은 `<br>`로 이어 쓰고, 읽으면 한 문단 안의 줄바꿈이 된다.
- `|`는 `\|`로 쓴다.

 | 인라인 수식 |

·주소 하나만 있는 글은 신호로 보지 않는다.
- **하지 않을 때**: Ctrl+Shift+V(일반 텍스트로 붙여넣기), 코드 블록·인라인 코드 안, 변환 결과가 스키마에 맞지 않을 때(기본 붙여넣기로 넘어간다 — 글을 잃지 않는다).
- **되돌리기**: 변환한 직후 **첫 Ctrl+Z는 붙여넣은 원문(일반 텍스트)으로 되돌리고**, 두 번째 Ctrl+Z는 붙여넣기 전으로 돌아간다. 구현은 첫 단계에서 표준 되돌리기로 붙여넣기를 취소한 뒤 원문을 새 편집으로 넣는 것이다(원문으로 "바꿔 넣는" 편집을 기록에 더하면 두 번째 Ctrl+Z가 변환된 내용을 되살린다). 붙여넣기는 앞선 입력과 한 되돌리기 단계로 합쳐지지 않게 끊는다. 그 사이에 다른 편집이나 커서 이동이 있으면 첫 단계는 건너뛰고 보통의 되돌리기가 된다. 확장 우선순위는 Collaboration(1000)보다 높은 1100이어야 한다 — 같으면 Yjs가 Ctrl+Z를 먼저 가져간다.
- **위키 링크**: 에디터는 `markdown: { resolvePage }` 옵션으로 페이지를 찾는다. 노트 앱은 제목이 같은 페이지가 **하나일 때만** 이어 주고(휴지통 제외), 없거나 여럿이면 글자(`[[…]]`)로 남는다. `[[제목#^id]]`는 블록 링크가 된다. 위키가 없는 소비자는 해석기를 주지 않으므로 항상 글자로 남는다.
- 이미지는 붙여넣기에서 가져오지 않는다(경로를 해석할 폴더가 없다) — 글자로 남는다.

## 복사 시 Markdown (옵션)

`createCoreExtensions({ copyAsMarkdown })`가 켜지면 복사할 때 `text/plain`이 Markdown이 된다(`MarkdownCopy.ts`). `text/html`은 그대로라서 에디터끼리의 복사와 웹 페이지 붙여넣기는 변하지 않는다. 글자 일부만 고른 복사도 서식(`**굵게**`)이 유지되고, 코드 블록 안의 글은 이스케이프 없이 코드 그대로다.
**기본은 꺼짐이고 노트 앱도 끈다** — 메모장 같은 곳에 붙이면 `**` 같은 기호가 보이기 때문이다. Obsidian으로 옮기는 용도라면 블로그·캘린더 같은 소비자가 켠다.

## frontmatter

가져오기에서만 해석한다(`---` 사이의 YAML 부분 집합: 문자열, 한 줄 목록, `- ` 목록). 내보내기가 쓰는 속성은 앱(전체 내보내기)이 정한다.

## 콜아웃

`> [!이름] 제목`의 **이름은 아무 것이나** 된다(Obsidian과 같다). 이름은 소문자로 시작하는 소문자·숫자·`_`·`-` 32자까지이고, 읽을 때 대소문자는 무시한다.

- **기본 5종**(`note`·`tip`·`important`·`warning`·`caution`)은 GitHub 알림이라 **대문자로 쓴다**(`> [!WARNING]`). 그 밖의 이름은 **소문자 그대로** 쓴다(`> [!rocket]`, `> [!info]`).
- **Obsidian 이름은 합치지 않는다.** `info`·`danger`·`success`·`question`·`bug` … 는 이름이 그대로 보존되고, 모양(아이콘·글)만 정해진 값을 쓴다(`CALLOUT_PRESET_META`).
- **아이콘**: 기본 5종·Obsidian 이름은 정해진 아이콘이 있고, 모르는 이름은 기본 아이콘(📝)이다. 소비자가 `EditorPorts.calloutIcons`(화면)나 렌더러의 `calloutIcons` 옵션으로 **이름별 아이콘 표**(이모지나 짧은 글)를 주면 모르는 이름도 원하는 아이콘이 되고, 정해진 아이콘도 바꿀 수 있다.
- **제목**(`title`): 표식 줄의 나머지(`> [!note] 제목`)는 서식 없는 한 줄 글로 `title` 속성에 둔다(종류 이름과 같은 글자는 기본 제목이라 생략). 없으면 종류의 기본 제목을 쓴다. 0.2까지는 굵은 첫 문단이 되었는데, 이미 그렇게 저장된 글은 그대로 읽힌다(소비자는 그것을 제목으로 볼지 정한다).
- **접기**(`fold`): `> [!note]-`는 접힌 채로, `> [!note]+`는 펼친 채로 시작하는 접을 수 있는 콜아웃이다(없으면 접지 않는다). 편집기에서는 아이콘 메뉴의 "접을 수 있음"으로 정하고, 제목 줄의 ▾/▸로 접고 편다(접은 상태는 화면에만 있다). 렌더러는 `<details>`로 그린다.
- Obsidian에서 정의하지 않은 이름은 기본 노트 모양으로 보이지만 내용은 그대로 읽힌다.

## 임베드 (`embed`, 옵션)

영상·게시물을 **주소 하나**로 끼워 넣는다. `createCoreExtensions({ embed: true })`(가져오기는 `ImportContext.embeds`, 렌더러는 기본 켜짐)로 켠다 — 노드를 더하는 것이라 노트 앱은 켜지 않는다.

| 공급자 | 알아보는 주소 | 정규화한 주소 |
|---|---|---|
| YouTube | `youtube.com/watch?v=`·`/shorts/`·`/embed/`·`/live/`, `youtu.be/`, `youtube-nocookie.com/embed/` (ID 11자) | `https://www.youtube.com/watch?v=ID` |
| X | `x.com`·`twitter.com`의 `/사용자/status/숫자` | `https://x.com/사용자/status/숫자` |
| Instagram | `/p/코드`·`/reel/코드`·`/tv/코드` | `https://www.instagram.com/p\|reel/코드/` |
| Pinterest | `pinterest.<도메인>/pin/숫자` | `https://www.pinterest.com/pin/숫자/` |
| SoundCloud | `soundcloud.com/사용자/곡` | `https://soundcloud.com/사용자/곡` |
| Bluesky | `bsky.app/profile/핸들 또는 DID/post/키` | `https://bsky.app/profile/…/post/키` (핸들은 소문자) |

- **쓰기**: `![](정규화한 주소)`, 크기가 있으면 `![|너비](…)`·`![|너비x높이](…)`(Obsidian의 이미지 크기 표기). 높이만 있는 크기는 쓰지 않는다. 크기는 100~2000의 정수.
- **읽기**: `![설명](주소)`의 주소가 위 공급자의 것이면 임베드 블록이 된다(주소의 `?si=` 같은 꼬리는 버린다). 문장 가운데에 있으면 문단을 갈라 블록으로 만든다. 일반 GFM 방언은 크기 표기를 읽지 않는다.
- **Bluesky의 DID**: `embed.bsky.app`은 DID(`did:plc:…`)만 받는다. 핸들 주소는 `embedSource`가 null이라 **원본 링크만** 보인다. 소비자가 `EditorPorts.resolveBlueskyHandle`(편집기: 핸들 → DID, 알아내면 주소를 DID 모양으로 바꿔 저장)이나 렌더러의 `blueskyDids` 옵션(서버: 미리 알아낸 핸들 → DID 표), 또는 `withBlueskyDid`로 DID를 주면 그려진다. 코어는 네트워크 요청을 하지 않는다.
- **안전**: 문서에는 **원래 주소**만 저장하고, 보여 줄 때 허용한 도메인의 iframe 주소만 만든다(`embedSource`). 주소에 계정 정보·포트가 있거나 http(s)가 아니면 거절한다. iframe에는 `sandbox`·`referrerpolicy`를 단다.
- **편집기**: `/임베드`가 빈 카드를 끼우고 주소를 붙여 넣어 Enter를 치면 공급자를 **주소로 알아낸다**. 지원하지 않는 주소는 안내만 보인다.
- **소비자의 개체**: 편집기가 모르는 주소는 `EditorPorts.parseEmbedInput`(글 → `{ kind, id }` 또는 null)을 거쳐 `reference` 노드가 될 수 있다(예: 블로그의 `https://내사이트/글/슬러그` → `{ kind: "post", id: "슬러그" }`). 이 노드는 Markdown에서 `![[슬러그]]`처럼 소비자가 정한 표기로 읽고 쓴다 — `ImportContext.references`(줄 → 대상)와 `MarkdownOptions.references.toMarkdown`(대상 → 줄)이 짝이다. `![[글]]`은 글 임베드, `![[series/이름]]` 같은 접두사로 종류를 나누는 것은 소비자의 몫이다.

## 들여쓰기 (`indent`, 옵션)

문단·제목의 `indent`(1~8단계, 한 단계 2em). `createCoreExtensions({ indent: true })`(가져오기는 `ImportContext.indent`, 렌더러는 기본 켜짐)로 켠다 — 속성을 더하는 것이라 노트 앱은 켜지 않는다. 문단마다 단계가 달라도 된다(1단계 다음에 3단계).

- **쓰기**: 줄 맨 앞에 `&emsp;`를 **단계 × 2개**(`&emsp;&emsp;글`이 1단계). 탭·공백은 코드 블록이 되거나 사라져서 쓰지 못한다. `&emsp;`는 눈에 보여서 원문을 고치거나 비교하기 쉽고 Obsidian 등 어디서나 들여쓰기로 보인다.
- **읽기**: 문단·제목 맨 앞의 `&emsp;`나 EM SPACE(U+2003) 개수를 센다(두 개 = 1단계, 홀수는 올림, 최대 8). 글 가운데의 `&emsp;`는 그대로 글자다.
- **편집기**: 문단·제목에서 `Tab`(늘리기)·`Shift+Tab`(줄이기). 목록은 `Tab`이 중첩, 표는 칸 이동, 코드 블록은 들여쓰기가 먼저 처리한다. 목록·표 안의 문단은 들여쓰지 않는다.

## 일반 GFM 방언 (`dialect: "gfm"`, 옵션)

`markdown-it`(`html:false`, `breaks:true`)처럼 **GFM에 위키 링크만 더한** 문서를 읽고 쓴다(PlanBench의 문서). 방언이 켜고 끄는 것은 `DialectProfile`(`dialect.ts`)에 모여 있다.

- **읽는 것**: GFM(표·할 일·취소선·코드), `[[대상]]`·`[[대상|표시 글자]]`(표시 글자에 `|`가 있어도 첫 `|` 뒤 전부; 대상의 `#`은 이름의 일부) → `pageLink`(`pageId` = 해석한 id, 표시 글자는 `label`). 가져오기 `resolvePage`가 대상을 id로 바꾸는데, 대상 글자를 그대로 돌려주면(`(t) => t`) 해석은 나중에 인덱스가 한다.
- **읽지 않는 것(글자)**: 콜아웃 `> [!NOTE]`, 수식 `$…$`·`$$…$$`, 각주, 줄 끝 `^id`, `![[임베드]]`.
- **원문으로 보존(`raw`·`rawInline`)**: HTML(블록·인라인), 이미지, 링크 속 이미지, 열 정렬이 있는 표 — 에디터에 대응 노드가 없고 대상 렌더러는 HTML을 글자로 보인다.
- **줄바꿈 한 개는 눈에 보이는 줄바꿈**(`hardBreak`)이고 내보낼 때 백슬래시 없이 그냥 줄바꿈이다(`hardBreakStyle`의 기본이 `newline`).
- **내보내기**: `pageLink`는 `[[제목]]`/`[[제목|표시 글자]]`(`pageTitle(pageId)`가 대상 글자를 돌려준다). `_`·`[`·`*` 앞에 `\`를 붙이는 이스케이프 정규화는 렌더 결과가 같다.
- **참조 설정**: `{{table:이름 rows=5}}` 같은 표기는 `references`(가져오기 함수·내보내기 `toMarkdown(kind, id, props)`)로 연결한다. 기본 표기는 `::ref{kind=… id=… rows=5}`(나머지 속성이 `props`).

## 방언 항목 덮어쓰기 (`profile`, 옵션)

방언 둘(`obsidian`·`gfm`)의 중간이 필요하면 가져오기 `ImportContext.profile`로 `DialectProfile`의 항목을 하나씩 덮어쓴다. 예: 블로그는 콜아웃·수식·각주는 Obsidian대로 읽고(`dialect: "obsidian"`), 이미지·HTML·열 정렬 표는 에디터가 구조를 모르므로 원문으로 보존하고(`rawEmbeds: true`), `/글-슬러그` 같은 상대 링크의 주소를 그대로 둔다(`keepAnyHref: true`, `mdLinksToPages: false`).

```ts
const ctx: ImportContext = {
  resolvePage: () => null,
  resolveImage: () => null,
  profile: { rawEmbeds: true, keepAnyHref: true, mdLinksToPages: false },
};
```

내보내기는 `dialect`만 본다(원문 `raw`·`rawInline`은 그대로 나가므로 따로 덮어쓸 것이 없다).

## 알려진 손실 (0.2)

내보냈다가 다시 읽으면 다음이 달라진다. 골든의 `lossless: false` 픽스처와 `*.imported.json`이 실제 모양을 보여 준다.

1. **블록 id**: 한 페이지 내보내기(`blockIds` 끔)에서는 사라지고 블록 링크는 페이지 링크가 된다. 전체 내보내기에서도 목록·인용·콜아웃·토글·구분선·페이지 블록의 id는 남지 않는다(글이 있는 블록의 id와 블록 링크는 남는다).
2. **페이지 카드**는 링크 한 줄이 되고, 읽으면 문단 속 페이지 링크가 된다.
3. **동기화 블록**은 그 자리에 복사되고 동기화 관계는 사라진다.
4. **표**: 병합 셀 풀림, 머리글 없는 표는 첫 줄이 머리글, 셀 안 문단 여럿은 한 문단.
5. **정렬**: 목록·표 안의 정렬은 쓰지 않는다. 왼쪽 정렬은 속성이 없는 것과 같다.
6. **빈 문단**은 사라진다.
7. **이미지**는 파일 경로가 되고 해시가 다시 계산된다. 크기는 Obsidian 형식이라 다른 편집기에서는 적용되지 않을 수 있다.
8. **콜아웃**의 제목은 서식 없는 한 줄 글이다(`> [!note] **굵게**`의 `**`는 글자로 남는다). 이름은 보존되지만 기본 5종 밖의 이름은 다른 편집기에서 기본 모양으로 보일 수 있다.
9. **임베드**는 주소가 정규화된다(`?si=` 같은 꼬리 삭제, `twitter.com` → `x.com`). 높이만 있는 크기는 쓰지 않는다.
10. **들여쓰기**는 `&emsp;`로 쓴다 — 지원하지 않는 편집기에서는 글자 사이의 공백으로 보이거나 `&emsp;`가 그대로 보일 수 있다.
9. **모르는 HTML**은 태그를 빼고 글자만 가져온다.
10. 안내 문구(`notices`)는 지금 한국어로만 나온다.

## 검증 상태

- 골든 픽스처 14개: 우리가 쓴 것을 우리가 읽는 왕복. 자동 시험.
- **Obsidian·Notion 실제 파일로는 검증하지 않았다.** 위 표의 Obsidian 호환은 공개 문서에 적힌 문법을 근거로 한 것이다. 샘플이 오면 `fixtures/`에 추가한다(P3-6).
